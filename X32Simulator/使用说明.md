# X32 虚拟调音台模拟器 — 使用说明

用 Mac 或 Windows 电脑模拟一台 Behringer X32 调音台，让手机上的 X32Remote App 在没有真机的情况下完成测试。

## 文件

| 文件 | 用途 |
|---|---|
| `x32_simulator.py` | 模拟器本体（Python 3，仅标准库，Mac/Win 通用） |
| `selftest.py` | 自测脚本：模拟 App 完整交互流程，14 项检查 |
| `install.sh` | **macOS 一键安装脚本**（自动装 Python 3 + 复制文件 + 建桌面启动器） |
| `X32模拟器.command` | macOS 双击启动器（免安装版，与 py 文件放一起双击即跑） |
| `启动模拟器.bat` | Windows 双击启动器 |

## 一键安装（macOS，推荐）

把 `X32Simulator` 整个文件夹拷到 Mac（U盘 / AirDrop / 微信均可），终端执行一条命令：

```bash
bash ~/Downloads/X32Simulator/install.sh    # 路径按实际位置改
```

脚本会自动完成：
1. 检测 Python 3；缺失则自动下载安装 python.org 官方包（3.11.9，支持 macOS 10.9+，含 10.14.6）
2. 模拟器复制到 `~/X32Simulator`
3. 桌面创建 **X32模拟器.command** 双击启动器
4. 生成卸载脚本 `~/X32Simulator/uninstall.sh`

之后日常使用：**双击桌面的 X32模拟器.command** 即可启动。

不想安装也可以：把 `X32模拟器.command` 和 `x32_simulator.py` 放同一文件夹，直接双击 `.command` 文件运行（前提是已装过 Python 3）。

## 一键启动（Windows）

双击 `启动模拟器.bat`（需已安装 Python 3 并勾选 Add to PATH）。

## 电脑端手动启动

```bash
python3 x32_simulator.py          # macOS / Linux
python x32_simulator.py           # Windows
python x32_simulator.py --port 10023 --bind 0.0.0.0   # 可选参数
```

启动后终端会实时打印每条收发的 OSC 指令。

## 网页控制台（试运行/演示界面）

启动模拟器后自动开启网页控制台（默认 `http://localhost:8080`）。手机/电脑浏览器都能打开。

**网络端口可以在网页上自由设置**：设置页 → 「🔌 网络端口」，填 OSC/UDP 与网页两个端口，
点保存。端口是进程启动时绑定的，**改完要重启模拟器才生效**（页面会明确提示「待重启生效」）。
两个端口不能相同；网页端口填 `0` = 关闭网页控制台。设置存在 `user_config.json`，下次启动自动沿用。

与手机 App 同构的 5 个页面：

- **卡片**：演出卡片列表与执行。每张卡由若干动作按时间轴串起来（可单步、可多步并行），支持通用动作 `set`（任意目标 + 值，天然跨控台）、原始 OSC 与「调用预设」；卡片可用 `next` 链到下一张形成流程。卡片页底部管理**台面预设**（可选范围）
- **混响**：FX 效果槽参数、Tap 定拍换算混响时间、与台面的双向同步
- **控制键**：自定义快捷键，点按按当前步长渐变增减指定推子
- **调音台**：32 通道 + 16 Bus + 8 DCA + 6 MTX + 6 Aux In + 2 USB + 8 FX 返回 + Main LR 的推子、静音、实时电平条（绿/黄/红）与 dB 读数（推子带电动式平滑动画，状态变化时缓动滑到新位置不跳变）
- **设置**：网络端口、控台型号（驱动层：X32 / M32 完整，Wing / Yamaha / A&H 待标定）、连接信息、场景号、配置导入导出、最近 OSC 收发日志

**台面预设（可选范围）**：卡片页 →「💾 保存预设（可选范围）」。先勾组（输入通道 / Mix Bus / DCA /
Aux In / USB / FX 返回 / Matrix / 主输出 / FX 机架 / 场景号），再勾参数（推子 / 静音 / 名称 / DCA 归属）；
编号留空 = 该组全部，也可以填 `1-8,13-16` 只挑几路。面板底部实时显示「将保存约 N 个值」。
回归时**只写范围内的参数**，没勾的通道一个字节都不动——这就是"只还原人声那几路"的做法。
预设随配置落盘，重启不丢（最多 8 条）。

**卡片里的「切换场景」有两种模式**：
- **全局调用**：整场按场景还原（真台上还受 Scene Safes 影响，App 覆盖不了）
- **局部调用**：**不发场景号**，只把某条预设范围内的参数应用过来；范围外的通道一个字节都不动

编辑器里选「局部调用」后会出现预设下拉；找不到预设时服务端会明确跳过并记日志，**不会退化成全局 recall**。
另有「📌 调用预设」动作可直接按渐变应用某条预设；「⚡ 通用设置」里的「⤓ 抓取台面值」按钮
一点就把当前值（百分比 / 秒 / 开或关 / 算法名）填进动作，省得手抄。

网页与 UDP 共享同一台虚拟调音台：在网页上推推子，手机 App 上会同步变化；手机 App 的操作也会出现在网页日志里——正好用来对照验证 App 界面与功能。

```bash
python3 x32_simulator.py --web-port 8080    # 命令行临时指定（优先级高于网页设置）
```

> 端口优先级：**命令行参数 > `PORT` 环境变量（线上部署时由平台注入）> 网页里保存的值 > 内置默认**。
> 命令行只影响本次运行，不会改写你在网页上保存的设置。

## 三种用法：先想清楚要控的是哪一台

| 你想做什么 | 手机侧怎么连 | 要电脑吗 |
|---|---|---|
| 熟悉界面 / 演示 / 开发调试（**没有真台**） | 浏览器打开 `http://电脑IP:8080` | 要（跑模拟器） |
| 用手机**管控真调音台**（推荐） | 装 App，填**真台 IP** + 端口 `10023` | **不要** |
| 用手机 App 连**电脑上的模拟器** | 装 App，填**电脑 IP** + 端口 `10023` | 要 |
| 用**浏览器**管控真调音台 | 浏览器打开 `http://电脑IP:8080`，且电脑以 `--bridge 真台IP:10023` 启动 | 要（电脑当网关） |

> ⚠️ **两个端口别搞混**：网页控制台是 **8080**（HTTP），App 直连是 **10023**（UDP/OSC）。
>
> ⚠️ **浏览器发不了 UDP**：不桥接时，网页上的操作只在电脑的虚拟台内生效，**控制不到真调音台**。
> 想真正管控真台，优先用手机 App 直连；或用电脑跑桥接模式，由电脑代发 OSC。

## 手机端连接

**通用前提**：手机与电脑在**同一局域网**（同一个 Wi-Fi，不是手机热点）。
模拟器启动时终端会直接打印出该用哪些地址，照抄即可：

```
X32 虚拟调音台已启动  UDP 192.168.50.57:10023
网页控制台已启动  http://localhost:8080  (手机/电脑浏览器均可打开)
iOS App 中把调音台 IP 填为: 192.168.50.57
```

### A. 用浏览器（网页控制台，零安装）

**最快的办法：扫码。** 启动后终端会打印一个二维码（`--no-qr` 可关闭），
手机相机/微信扫一下就直接打开控制台，不用照抄 IP：

```
手机扫码直达 (同一 WiFi): http://192.168.50.57:8080/  [--no-qr 可关闭]
████▄▄▄▄▄█████  ...（半块字符组成的二维码）
```

电脑上已经打开了网页控制台的话，也可以进 **设置 → 手机 / 安卓平板连接**，
那里同样有二维码，旁边还有「📋 复制地址」按钮。

手输地址的老办法（二维码扫不出来时用）：

1. 上面第 2 行的 `localhost:8080` 是给电脑自己看的，**手机要换成电脑的局域网 IP**：
   即 `http://192.168.50.57:8080`（IP 以你终端实际打印的为准）
2. 查电脑 IP：Windows `ipconfig` 看 IPv4 地址；macOS 系统设置 → 网络
3. 手机浏览器打开即用，**不用装任何东西**
4. 安卓 Chrome 菜单 →「添加到主屏幕」，之后就像 App 一样全屏使用

### B. 用原生 App

1. 打开 X32Remote App → 设置 → 调音台 IP 填电脑 IP，端口 `10023`
2. 或直接点"自动发现"扫描 —— 模拟器会正常响应 `/xinfo` 探测
3. 扫描到的地址会被记住，下次打开自动回连

> ⚠️ **Windows 首次运行会弹防火墙提示，必须点「允许访问」**（勾上"专用网络"）。
> 误点"取消"的话手机就会一直连不上 —— 这是最常见的失败原因。
> 补救：Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙 → 勾上 Python。

## 自动增益 / 自动推子

网页控制台第 5 个页签「自动」（在"控制键"右边）：给某一路设一个目标电平（默认 **-18 dBFS**），
它会读电平表、自动走**推子**或**数字增益**把这一路稳住。

- **推子 / 增益**：推子模式动推子（接真台看得见电动推子在走）；增益模式动 `preamp/trim`，推子不动
- **慢 / 中 / 快**：改的是「平均窗口 / 死区 / 每秒最大修正」，不是"灵敏度"三个字了事
- **不会抽**：先做功率平均、再判死区、最后限速 —— 所以它跟着句子走，不是每个字拉一下
- **静音不动**：低于 -80 dB 冻结（不会把静音往上推成噪声）
- **人优先**：你手动拖了推子，它让位 2 秒，之后从新位置继续
- **量程**：默认 ±12 dB（可调 3-24），到顶停手

配置存在 `user_config.json` 的 `rider` 键；接口是 `GET/POST /api/rider`，
接真台时写入走同一条桥接管道（`source="auto"`，转发限速 100 ms）。

## 模拟的行为

- **自动发现**：响应 `/xinfo`（name=X32Remote-Sim, model=X32）
- **32 通道 / 8 DCA / Main LR**：推子、静音的查询与设置（含 `*` 通配符查询，以 Bundle 回包）
- **电平表**：订阅 `/meters/1` 后每 150ms 推送 32 通道电平 blob，电平随推子位置动态起伏（静音通道为 -∞）；发送 `/meters/1` i 0 退订
- **接受 Bundle 形式的指令**（App 未来如批量发送也兼容）

## 自测

```bash
python3 selftest.py [模拟器IP]    # 默认 127.0.0.1
```

覆盖：xinfo 发现、单条/通配符查询、推子与静音设置回读、DCA 补零地址、Main LR、Bundle 收发、电平表订阅/退订。

## 关于 macOS 10.14.6 的说明

- ✅ **当模拟服务器**：完全可行。安装 python.org 的 Python 3（3.9.x 支持 10.9+）即可运行。
- ❌ **当开发机编译 iOS App**：Mojave 最高支持 Xcode 11.3（Swift 5.1），而本项目使用 async/await（需 Xcode 13.2+）与较新 SwiftUI，无法编译。编译 App 需 macOS 12.5+ / Xcode 14+（对应支持的机型）。
- ✅ 手机 App 编译好后，日常演出/排练时仍直连真调音台；电脑模拟器主要用于开发调试与演示。

## 推荐拓扑

```
开发/测试:  iPhone(App) ──Wi-Fi──> 电脑(Mac/Win, Python 模拟器 :10023)
真实使用:  iPhone(App) ──Wi-Fi──> X32/M32 调音台 (:10023)
```

两端协议一致，App 内只需切换 IP 地址，无需改代码。
