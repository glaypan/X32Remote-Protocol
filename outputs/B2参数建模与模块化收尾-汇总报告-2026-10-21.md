## 1. 这次到底改了什么（一句话版）

以前"增益/反相/延时/低切/插入/噪声门"这 12 个通道参数只存在于**界面和文档**里：卡片能配、预设能勾，但台面状态里根本没有这些字段，写下去要么被通用分支按 `[0,1]` 钳成 1，要么直接丢失。本次把它们做成**一等公民**，并把"新增一个参数要改五处、漏一处就静默失效"的老结构换成了**一张登记表**。

## 2. 架构：ParamSpec 表驱动（新增 `x32sim/params.py`）

一个参数的五个事实原先散落在五个文件里，现在合成一行登记：

| 事实 | 原先在哪 | 现在 |
|---|---|---|
| 状态字段名 | `state.MixerState` | `ParamSpec.field` |
| OSC 地址 | `consts.FADER_ADDR` + `profiles.addr` | `ParamSpec.osc` |
| 量程与钳制 | `state.set_value` 里逐个 `_clamp01/_truthy` | `param_coerce`（统一 clamp + 量化） |
| 白名单 | `consts.SET_PARAMS / PRESET_GROUP_PARAMS` + 前端硬编码 | 同一张表推导 |
| 出厂值 | 没人知道，只在注释里 | `ParamSpec.default` + `note` |

**边界（有意的设计决定）**：只收「按路存储的标量参数」。名称（存在 `STATE.names`）、DCA 归属（位掩码投影）、FX 机架（参数号随算法变化）**故意不入表**，继续走显式分支——把它们塞进来只会得到一堆永远为真的 `if`，不会得到复用。

## 3. 12 个参数的协议标定

地址/类型/量程逐条对齐 **Behringer X32 Protocol Manual**（M32 同协议）：

| 参数 | OSC 地址 | 量程 | 档位 | 出厂值 | 备注 |
|---|---|---|---|---|---|
| 增益 trim | `/ch/%02d/preamp/trim` | −18 … +18 dB | 0.25 dB | 0 dB | 手册 [−12,12]（仅数字源）vs 非官方 [−18,18]，**取宽并注释** |
| 反相 invert | `/ch/%02d/preamp/invert` | 0 / 1 | — | 0 | 极性反转 |
| 延时开关 | `/ch/%02d/delay/on` | 0 / 1 | — | 0 | |
| 延时时间 | `/ch/%02d/delay/time` | 0.3 … 500 ms | 0.1 ms | 0.3 ms | 手册 `linf[0.300,500.000,0.100]`，**下限不是 0** |
| 低切开关 | `/ch/%02d/preamp/hpon` | 0 / 1 | — | 0 | |
| 低切斜率 | `/ch/%02d/preamp/hpslope` | {12,18,24} | 枚举吸附 | 12 | 按**字面值**传（.scn 导出同款）；真机若按索引回 0/1/2 会吸附成 12/12/18，不静默变 0 |
| 低切频率 | `/ch/%02d/preamp/hpf` | 20 … 400 Hz | **101 对数档** | 80 Hz | 手册 `logf[20,400,101]`；出厂值需真机确认 |
| 插入开关 | `/ch/%02d/insert/on` | 0 / 1 | — | 0 | |
| 插入位置 | `/ch/%02d/insert/pos` | {PRE,POST} → 0/1 | 枚举 | PRE(0) | 需真机确认 |
| 噪声门开关 | `/ch/%02d/gate/on` | 0 / 1 | — | 0 | |
| 门限 | `/ch/%02d/gate/thr` | −80 … 0 dB | 0.5 dB | −40 dB | 需真机确认 |
| 门范围 | `/ch/%02d/gate/range` | 3 … 60 dB | 1 dB | 15 dB | 正值=衰减量；需真机确认 |

> 「需真机确认」= 公开资料没有载明出厂值。模拟器给一个合理值，但不假装核对过——每一条都写在 `ParamSpec.note` 里。

## 4. 八层接线（每一层都有对应的回归项）

1. **地址映射** — `profiles.addr` 表驱动优先（`spec_addr`，main 系列无 `%02d`），未知 kind 返 `None` 并记日志
2. **STATE** — `blank_row()` 生成 8 组行字典；`ch` 行从 2 字段扩到 **14**
3. **钳制** — `param_coerce`：bool → `_truthy`（认 "0"/"false"/"off"），其余 `_finite` + clamp + 量化
4. **白名单** — `SET_KINDMAP` / `SET_PARAMS` / `PRESET_GROUP_PARAMS` / 标签表全部由同一张表推导
5. **读回** — `match_address` 新增 `(seg2,seg3)` 索引分支支持通配符；`value_reply` 按 `vtype` 发 float / int
6. **桥接转发** — `_bridge_forward` 改表驱动定类型，另加 `isfinite` 拒发闸
7. **卡片 set 动作** — `_clean_set_action` 走登记表清洗（存进去的值 = 执行的值）
8. **预设 scope** — 抓取/回归只写范围内的键；越界编号靠 `target_exists` 跳过（脏配置不炸回归线程）

### 顺带修掉的两个真 Bug

- **桥接转发类型错**：原判定 `kind.endswith("_fader") → float, 其余 → _truthy`。新增参数全是非 `_fader` 结尾，于是 `trim 3.5 dB` 会被压成 `1` 发给真台——"本地看着对、真台完全不对"的那类故障。现按 `ParamSpec.vtype` 分发。
- **卡片 set 动作静默改值**：`_clean_set_action` 的兜底分支按 `[0,1]` 钳制，`trim 3.5` 存进卡片就变成 `1`。现按参数自己的量程清洗。

## 5. 前端（web 三文件 + 合成）

- **通道参数面板**：通道条编号变成入口（有任一处理启用时右上角亮橙点），点开是底部面板 12 个控件——滑块（增益/延时/频率/门限/门范围）、两态按钮（反相/延时/低切/插入/门）、下拉（斜率 12/18/24、位置 PRE/POST）。从属项在主开关关闭时变淡但仍可调（"先设好参数再开开关"是真实工作流）。
- **卡片「通用设置」**：12 个参数进入参数下拉，按类型给滑块步长/单位/下拉；布尔类不再走数值输入框。
- **预设范围**：12 个参数作为可勾选项（仅输入通道可用），勾上即进 scope。
- **防漂移护栏（新增 A8）**：`test_params.py` 会解析 `web/app.js` 的 `CH_PARAM_UI`，逐项比对字段名/量程/档位/默认值与后端 `PARAM_SPECS`。前端是"第二份量程表"，不比对就会静默分家（界面能拖到 400、后端只认 250）。

## 9. 仍需关注（不要当成已完成）

1. **`/api/state` 全量广播**：轮询侧已做增量指纹（命中不变只回 ~30 字节），但本地订阅者广播（`MAIN_SOCK`）仍是高频全量。真台/长时间挂机下的 4G 流量账没结清（原 271–300 MB/h）。
2. **十项参数只做了前 5 类**：压缩、EQ、发送、Pre/Post 仍**未建模**。表驱动结构已就位，补它们是"加行 + 三处白名单"，但要先核实各自的 OSC 地址与量程（压缩/EQ 的参数号在真台是按段索引的，比这 12 个复杂）。
3. **5 处出厂值待真机确认**：低切频率/斜率、插入位置、门限、门范围。模拟器给的是合理值，不是核对值。
4. **trim 量程取宽**：手册 [−12,12] 与非官方 [−18,18] 冲突，现取 [−18,18]。若真机只认 ±12，写入 −15 会被真台钳到 −12，本地/真台会出现差值——需要在真机上确认后收窄。
5. **hpslope 索引制风险**：按字面值传是我基于 `.scn` 导出的判断；若真机回 0/1/2，吸附会落到 12/12/18（不静默变 0，但不精确）。
6. **模块化 B4 的 WriteSink 未落地**：`state.set_value` 里仍直接调 `bridge._bridge_forward`。当前行为正确，但"切断 state→bridge"的解耦目标还差一步。
7. **移动端面板只有滑块**：没有键盘精调入口。精确值目前靠卡片 `set` 动作或 API；若要更顺手，可加"点数值弹数字键盘"。
8. **双形态维护成本**：`x32_simulator.py` 是生成物，必须 `make_single` 同步（CI/回归会挡，但改文件时容易忘）。
