# 台面预设 · 场景全局/局部调用 · 卡片参数抓取 —— 参数清单与设计

> 事实基线：`X32Simulator/x32_simulator.py`（权威实现，5900 行）+ 共享协议规范 v1.5。
> 本文先把「到底有哪些参数可存」列清楚，再给三个功能的落地方案。

## 一、可保存的参数清单（模拟器/三端**已建模**的部分）

### 1.1 按路数×参数

| 参数组 | 路数 | 每路可存参数 | 说明 |
|---|---|---|---|
| 输入通道 `ch` | 32 | 推子 `fader`、静音 `on`、名称 | 另有 DCA 归属（位掩码，见下） |
| Mix Bus `bus` | 16 | 推子、静音 | |
| DCA `dca` | 8 | 推子、静音 | 成员关系存在通道侧 |
| Aux In `auxin` | 6 | 推子、静音 | |
| USB 播放 `usb` | 2 | 推子、静音 | |
| FX 返回 `fxret` | 8 | 推子、静音 | |
| Matrix `mtx` | 6 | 推子、静音 | |
| Main LR `main` | 1 | 推子、静音 | 地址无 `%02d` |
| FX 机架 `fx` | 8 | 算法 `type`、名称、开关 `on`、混合比 `mix`、参数 | 参数仅混响类：时间/预延迟/阻尼 |
| 全局 | — | 当前场景号、控台型号 | |

### 1.2 数量核算

| 项 | 数量 |
|---|---|
| 推子 + 静音（79 路 × 2） | **158** |
| 名称（79 路） | **79** |
| DCA 归属（32 通道 × 8 位掩码） | **32** |
| FX 槽位属性（8 槽 × 算法/开关/混合比） | **24** |
| FX 算法参数（8 槽 × 3 个 × 仅混响类） | **24** |
| 当前场景号 | **1** |
| **合计可存值** | **约 318** |

### 1.3 真台有、但**当前完全没建模**的参数（重要）

| 参数 | 真台 OSC 地址 | 现状 |
|---|---|---|
| 通道→母线发送电平（32×16 条） | `/ch/NN/mix/BB/level` | 无控件、无状态、无校验 |
| 声像 | `/ch/NN/mix/pan` | 同上 |
| 通道 EQ（4 段 + 高切/低切） | `/ch/NN/eq/...` | 同上 |
| 动态（门限/压缩） | `/ch/NN/dyn/...`, `/ch/NN/gate/...` | 同上 |
| 增益、幻象电源、极性 | `/ch/NN/preamp/...` | 同上 |
| 通道颜色、静音组 | `/ch/NN/config/color`, `/config/mute` | 同上 |

**结论**：所谓「通道里面的所有参数」，在**当前产品**里就是 1.1 表内那几项；要做到真台意义的"所有"，
必须扩协议（v1.6）+ 模拟器建模 + 三端控件，这是一期工程而非一个字段。

## 二、现状：已有的「快照」能力（可直接演进）

`SNAPSHOTS` 目前的行为（`x32_simulator.py:2032`）：

- 保存内容：**8 组全部路**的 `fader` + `on`（不含名称、DCA 归属、FX）
- 容量：用户预设 8 个（先进先出）；另有 5 个自动撤销点（每次卡片执行前存）
- 回归：静音立即生效，推子按 0.5–15 秒平滑滑回；回归中可被打断
- 缺口：**没有范围选择**、不能只存某几路、不能存 FX/名称

## 三、功能一：台面预设（可选保存范围）

### 3.1 预设数据模型

```json
{
  "id": 7,
  "name": "主唱耳返-开场",
  "time": "01:20:33",
  "scope": {
    "groups": ["ch", "bus", "main"],
    "params": ["fader", "on"],
    "indices": {"ch": [13,14,15,16], "bus": [15]}
  },
  "data": { "ch": {"13": {"fader":0.72,"on":1}}, "bus": {"15": {"fader":0.66}} }
}
```

- `scope` 缺省 = 全组 × 推子+静音（旧快照自动兼容，无需迁移）
- `indices` 缺省 = 该组全部；支持 `1-8,13-16` 区间写法

### 3.2 界面（保存时的范围选择）

三层勾选，默认只勾第一层最常用的两项：

1. **组**：输入通道 / Mix Bus / DCA / AuxIn / USB / FXReturn / Matrix / Main / FX 机架 / 全局
2. **参数**：推子 / 静音 / 名称 / DCA 归属 / FX 算法与参数 / 混合比
3. **编号**：全部，或逐个勾选（提供区间输入）

底部实时显示「本次将保存 N 个值」——让用户对范围有确切预期。

### 3.3 回归语义（防「以为是局部，结果全变」）

- **只写 scope 内的键**，未纳入的通道一个字节都不动
- 不一致要显式：scope 里没有的组，回归后在提示条上写「未包含：FX 机架」
- 过渡时间沿用现机制（0.5–15s，推子滑、静音瞬切）

## 四、功能二：卡片「切换场景」的全局 / 局部

### 4.1 必须先说清的真台限制

- OSC 只有 `/scene/N/load`（**整场 recall**），**没有"只 recall 场景一部分"的地址**
- 真台的选择性 recall 靠 **Scene Safes**：那是台子级的全局开关，且由人在台子上配置
- 因此「局部调用」只有两条路：客户端预设应用，或客户端逐参数动作序列

### 4.2 动作模型

```json
{ "kind": "scene", "scene": 7, "mode": "global", "settle": 0.6 }

{ "kind": "scene", "scene": 7, "mode": "partial",
  "source": "preset", "presetId": 12,
  "scope": { "groups": ["ch"], "params": ["fader","on"], "indices": {"ch": [1,2,3,4]} } }

{ "kind": "scene", "scene": 7, "mode": "partial",
  "source": "actions", "actions": [ {"kind":"set","target":{"group":"ch","id":1,"param":"fader"},"value":0.7} ] }
```

- `mode=global`：发 `/scene/N/load`（受真台 safes 影响，App 无法覆盖）→ 需在 UI 明说
- `mode=partial` + `source=preset`：**不发场景号**，只按 scope 应用 App 侧保存的该场景预设
- `mode=partial` + `source=actions`：逐参数写（最精确，卡片会变长，提供「从台面抓取生成」）
- `mode=partial` 且找不到对应预设 → **明确失败并提示**，绝不能静默退化成全量 recall
- `settle`：切换后的等待（真台 `/load` 的状态回复早于实际生效）

### 4.3 界面

场景动作编辑区：先单选「全局调用 / 局部调用」；选局部后出现「用哪个预设 / 用动作列表」，
并在下方常驻一行灰字：*全局调用会把舞台上所有参数按场景还原，包括你没在卡片里写过的通道。*

## 五、功能三：卡片调整通道参数 + 抓取实时值

### 5.1 现成能力（不用开发）

`set` 动作已经是通用的「目标 + 值」：`{"group":"ch","id":3,"param":"fader"}` + `value`，
支持 ch/bus/dca/auxin/usb/fxret/mtx/main/fx/scene；另有 `fade_ch`、`mute`、`rel_db`；
`osc` 动作可发任意原始地址（真台上能写发送、EQ）。

### 5.2 要补的四件事

1. **「⤓ 抓取台面值」按钮**：对当前动作的目标读实时值填入（推子显示 dB、静音显示开/关、FX 参数按原生单位）
   - 有真台桥接时**读真台回读值**，不读本地镜像；离线/未桥接时按钮置灰并提示
2. **「整台抓取为预设」**：一键把当前台面按当前 scope 存成预设（= 功能一）
3. **新增 `preset` 动作**：卡片直接调用预设（带 scope 与过渡秒数），把「局部调用」做成可复用积木
4. **字符串参数**：卡片目前只收数值。要支持「改通道名」需放开 `name` 类参数（白名单 + 长度上限 + `esc()`）

## 六、建议的落地顺序

## 七、三个需要你定的问题

1. **范围粒度**：两层（组 × 参数）够用，还是要精确到单通道？（推荐两层 + 单通道可选）
2. **「所有参数」的范围**：先做已建模的 318 个值，还是要连**发送/EQ/动态**一起做（= 扩协议 + 模拟器建模，工作量大一个量级）？
3. **局部调用的实现**：走 App 侧预设（不依赖真台，推荐），还是依赖真台 Scene Safes（需人工在台子配好，App 只能提示）？
