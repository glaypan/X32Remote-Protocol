# X32 Remote v1.2.0

> **本版主题：契约三连升（v1.3 → v1.5），服务端与网页试用版完成一轮系统性加固。**
>
> 自 v1.1.1 以来，共享协议规范连升三个小版本：混响控制与同步（v1.3）、控台驱动层（v1.4）、输入消毒与「假成功」防线（v1.5）。iOS / Android 两端 App **无代码变动**，安装包为同源码重新构建，与 v1.1.1 等效。

适配 **Behringer X32 / Midas M32** 数字调音台，走 OSC over UDP（端口 10023），手机与调音台同处一个局域网即可直接控制，不依赖中间服务。

## 二、v1.3 混响控制与同步

- FX 地址两个坑（都与 DCA 恰好相反）：**槽号不补零、参数号补零** `/fx/1/par/01`；参数吃**原生单位**（秒 / 毫秒）
- 算法 → 参数索引做成数据表，**换算法整表重铺**，否则索引「串味」
- **Tap 定拍**：抖动 `<0.15s` 忽略、`>2.0s` 重开、最近 8 个间隔均值、BPM 钳 `[30,300]`
- **时值换算**：`秒 = 拍数 × 60 / BPM`，附点 ×1.5，按算法范围钳制
- **三种模式** `software` / `console` / `both`；防回环**双闸门**（`source="action"` + 回声抑制，容差 `max(0.02, |值|×0.5%)`）

> 落地边界：混响**卡片动作**未进 iOS / Android 白名单（保持 12 种，避免配置互不兼容）；两端既有 FX 直控不受影响。

## 三、v1.4 控台驱动层

- `(kind, idx)` 语义管道 → `ConsoleProfile.addr()` 翻译真实地址；返回 `None` = 不支持，**记日志后跳过**
- `ready` / `verified` 两级：未标定控台 `ready=false`，**所有写入被拒并记日志**（地址蒙错比不动作难排查得多）
- 动作白名单 12 → **14 种**：新增通用动作 `set`（跨控台）与原始 OSC 动作 `osc`（控台专有）
- **M32 与 X32 同协议**（Midas 贴牌）→ 驱动继承，只换显示名；Wing / Yamaha / A&H 仅骨架

## 四、v1.5 输入消毒与「假成功」防线（本版重点）

**核心原则：假成功比报错更难查。** 报错会逼人看日志；「返回 ok 但什么都没发生」能沉寂几个月。

### 1. NaN 双闸（曾能让界面永久卡死）

`min(max(float(v),0),1)` 对 NaN **全部穿透** → NaN 顺 `json.dumps` 成字面量 → 前端每轮询 `JSON.parse` 必抛 → **界面永久卡死**，且 NaN 被写盘 → 重启也治不好。

入口层三层归一化（`_finite` / `_truthy` / `_clamp01`）+ 输出层 `_sanitize_snapshot` 递归替换 + `allow_nan=False` 让漏网的**在测试阶段就炸**。

### 2. 卡片 API 显式校验

`/api/cardadd`、`/api/cardedit` 曾接受平铺报文：cardadd 报不对题的「actions 不是数组」，cardedit **静默 ok 而什么都没改**。现要求 `{"card": {...}}` 包裹，缺包裹明确 400 并点名。

### 3. 丢弃明细透到前端

`_clean_actions()` 返回 `(actions, dropped)` —— 提交 10 个丢 2 个，toast 告诉你哪两个、为什么。

### 4. 保存期 vs 执行期

保存期只做格式清洗；范围校验移到执行期（`_filter_targets()` + `target_exists()`，跳过并记日志）。X32 下存「写到第 40 路」的卡片，换到 48/64 路台子直接生效。

### 5. XSS 防线

全前端 `esc()`（通道名 / 卡片名 / 图标 / FX 名 / 快照名 / `/api/scan` 真台名**全部外部可控**，含局域网任意机器；项目无鉴权、监听 0.0.0.0）。CSP 开 `'unsafe-inline'`（单文件内联，拆外部文件才能收紧）+ `frame-ancestors 'self'` / `object-src 'none'` / `base-uri 'self'`。

## 五、效果库归属控台驱动（规范 §4.6）

`ConsoleProfile.fx_algos` 是效果库**唯一归属**，`fx_algos()` 是**唯一取数口** —— 任何「按算法查参数索引」的地方都必须走它，否则换控台**参数串味**。

- X32 / M32 **独立深拷贝**（把「将来效果库会分化」写进结构里）
- 未标定控台 = 空库：混响页「只能看不能写」，写入被拒并记日志
- 切台时不在新库里的算法槽**明确置空**（不留僵尸槽）
- 每槽 `loaded` / `known` **两个独立布尔**：真台装了本库没有的算法是「未知」不是「空槽」
- 新增「从真台同步效果」`fx_pull_from_console()`

## 六、修掉一个真实缺陷：桥接冲突检测被渐变挤掉

本地渐变每 50ms 转发 → 真台把转发也当手动变更 → 干预到达时节流几乎恒成立 → 立即推送被丢 → 150ms 周期推送时干预值已被下一 tick 覆盖 → 推出的值等于渐变值 → 被当回声吸收。**干预信号被挤掉两次，冲突永远检测不到。**

修法：节流必须**连同值一起判断**。修复前 `test_bridge_p2.py` 单跑 8 次挂 4 次；修复后 8/8，全量回归连续 3 轮稳定。

## 十、升级注意

1. **iOS 需要 iOS 17+**，iOS 16 及更低装不上。
2. **iOS 卡片库回落到出厂卡片**：两代格式差异大，不做自动迁移 —— 自动转换容易产生错误动作，宁可重配。
3. 首次连接申请**「本地网络」权限**（OSC 通信与自动发现）。
4. **Android 无破坏性变更**，直接覆盖安装。
5. 服务端改过端口的话，重启后按设置页的值生效，命令行参数优先级最高。

---

## 十一、已知限制

- **iOS IPA 必须自行签名**：免费账号 7 天重签是硬限制。
- **iOS 不能后台常驻**：约 30 秒被挂起，只能当前台遥控器。需常驻请用 Android。
- **Android 无桥接模式**：它本身等效于桥接，不需要中转层。
- **混响卡片动作未进 iOS / Android**：白名单保持 12 种，见第二节。
- **真机联调项待实测**：OSC 连发最小间隔、真台推送延迟、`/xremote` 保活表现。
- **Wing / Yamaha / A&H 仅骨架**：`ready=false`，写入被拒并记日志（宁可不动也不蒙地址）。
