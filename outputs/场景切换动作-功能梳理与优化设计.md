# 演出卡片「切换场景」动作 — 功能梳理与优化设计

> 版本：v1.0（设计稿，未实现） · 2026-10-19 · 覆盖 WebDemo / 模拟器 / iOS / Android 四端

---

## 1. 现状盘点：四端一致的最小实现

| 端 | 现状 |
|---|---|
| 协议规范 | `scene` 动作唯一参数 `scene: Int(1–99)`；地址 `/scene/%d/load`（不补零） |
| 服务端（x32_simulator.py） | 保存期钳 1–99；执行期置 `STATE.scene` 并发 `/scene/N/load`；无名称、无过渡、无重试 |
| WebDemo 卡片编辑器 | 只有一个数字输入框「场景号」 |
| iOS / Android | 同样只有 `scene: Int`；写入 `/scene/N/load` |

**结论：编号是唯一真相，名称在四端都不存在。** 一切优化都建立在「执行层不动、新增名称映射层」的前提上。

---

## 2. 方案概述

- **执行层零改动**：卡片执行仍只发 `/scene/N/load`（编号），不引入协议破坏性变更，旧卡片全文兼容。
- **新增「场景名映射层」**：编号 ↔ 名称的本地映射表，随 `user_config.json` 导出/导入；界面消费名称，执行消费编号。
- **数据三层来源**：真台 OSC 查询（主）/ X32-Edit `.scn` 导入（备）/ 手动命名（兜底），经同步引擎增量合并。
- **过渡时间不放进场景动作**：OSC 场景加载是台面瞬时动作，协议本身没有"场景渐变"概念；需要听感过渡时，用现有 `fade_all` / `fade_ch` 动作序列在切换前后包夹实现（先压音量再切场景再恢复）。

---

## 3. 配置项盘点（现状 → 建议）

| 配置项 | 现状 | 建议 | 必填/可选 | 说明 |
|---|---|---|---|---|
| `scene` 场景编号 | 有 | 保留 | **必填** | 1–99；执行的唯一真相 |
| `name` 名称回显 | 无 | 自动带出（只读） | 可选（自动） | 从映射表按编号取，仅用于展示，不参与执行 |
| `settle` 切换后等待 | 无 | 新增，秒级，默认 0 | 可选 | 台面 recall 需要时间；>0 时推迟卡片内后续动作，避免"场景还没切完就推子" |
| `retry` 失败重试 | 无 | 新增 0–2 次，固定间隔 | 可选，默认 0 | OSC 无握手，重试只对"发送失败"有效，不对"台面拒绝"有效——文案须说清 |
| `skip_if_current` 已是当前场景则跳过 | 无 | 新增，默认开 | 可选 | 避免重复加载同一场景把台面状态冲掉 |
| `at` 执行时机 | 有（时间轴偏移） | 保留 | 可选 | 卡片内相对/绝对时机，沿用现有语义 |
| 前置条件 | 无 | **不新增字段** | — | 用卡片链 `next` + `wait` 表达，避免第二套条件语法 |
| ~~场景过渡时间~~ | 无 | **不做** | — | OSC 无此能力；见 §2 末条 |

**遗漏参数提示**：失败重试若要做，必须在 UI 上明示"只保发送不保生效"——否则就是新的"假成功"。

---

## 4. 数据来源（三层）

1. **真台 OSC 查询（主来源）**
   - 逐号读名：`/-show/scene/<n>/name`（X32/M32 Unofficial OSC Protocol）
   - 批量读名：`/showdump`（一次拿当前 Show 的 cues / scenes / snippets 全部名称，优先用它，避免 100 个场景逐号往返）
   - 场景编号范围 0–99（0 为出厂基准场景）
2. **`.scn` 文件导入（备来源）**：解析 X32-Edit 保存的场景文件，离线拿到名称表。
3. **手动命名（兜底）**：无真台、无文件时，用户在映射表里直接改名。

三层都汇入同一张本地映射表；映射表是卡片编辑器唯一读数口。

---

## 5. 联动机制

**同步触发时机（四种，可单独开关）**
- 打开卡片编辑器时自动同步一次（最常用）
- 手动点「从真台同步场景名」按钮
- 定时轮询（默认关；桥接连上台时同步一次即可）
- 桥接回读：执行切场景后，台面回声到达时顺带刷新当前场景名

**合并策略（增量合并，四条规则）**
1. 真台名优先于本地旧名；
2. **不覆盖用户改过的名**（本地打 `userEdited` 标记；真台名进 `consoleName` 字段并存展示）；
3. 每条记录带时间戳，界面显示"同步于 HH:MM"；
4. 空名 / 未占用槽位跳过，不生成占位垃圾。

**冲突处理**
- 真台上场景被改名/删除 → 以真台为准，用户备注保留为次要字段；
- 卡片里存的编号在真台上不存在 → 执行时记警告日志 + 界面标黄，**不阻断卡片**（演出优先）；
- 同步期间用户正在编辑器里选择 → 用现有脏标记思路防止轮询冲掉输入。

## 6. 界面改造方案（场景可读化）

**卡片编辑器 · 动作参数区**（核心改动）
- 数字框 → **「编号 · 名称」选择器**：下拉直接列出 `3 · 独唱` 这样的名称列表；
- 编号辅助保留：名称旁小字显示编号，鼠标悬停完整显示 `#3 独唱（真台同步）`；
- 搜索框：支持编号 / 名称 / **拼音首字母**匹配；
- 高级入口：折叠的"手动输入编号"，满足临时跳号；
- 来源徽标：每项标注 真台 / 导入 / 手动；
- 当前场景高亮 + 置顶「当前场景」项。

**其他界面**
- 混音页 / 状态栏的场景徽标从「场景 3」升级为「场景 3 · 独唱」；
- 新增「场景名管理」面板（在设置页）：查看/编辑映射表、执行同步、导入 `.scn`、导出。

---

## 7. 配置步骤

1. 设置页桥接真台（填 IP，OSC 端口 10023，同一局域网）；
2. 打开场景名管理面板，点「从真台同步」；
3. 核对名称，缺名的手动补；
4. （可选）导出映射表随配置备份；
5. 之后建卡片时，切换场景动作直接从名称列表选。

---

## 8. 已知限制

- **OSC 没有场景过渡时间**：`/load` 是瞬时动作；"淡入淡出换场景"必须用 fade 动作序列包夹（§2）。
- **`/load` 的状态回复早于实际生效**：台面 recall 需要时间，这是 `settle` 字段的存在理由。
- **Scene Safes 决定 recall 范围**：Routing / Output Patch / HA / Config / Channel Processing / Mix Buses / Effects / Talkback 各组"安全开关"影响哪些参数会被场景覆盖——软件只能提示，不能代管。
- **编号口径待真机联调**：X32 场景编号 0–99（0 是出厂基准），而软件历史口径是 1–99；0 号能否被 `/load` 加载需实测后决定是否放开。
- **未桥接时只有手动名**：名称功能离线可用但只剩第三层来源。
- **`.scn` 解析依赖文件格式**：X32-Edit 版本差异可能造成个别名称读不出，按"跳过并记日志"处理。

---

## 9. 易用性建议（降低学习成本）

1. **默认预填「下一个场景」**：打开切换场景参数时自动带出 `当前场景 + 1`——演出中绝大多数切换是顺序进行，一步到位。
2. **演出流程模板**：内置示例卡片链（开场 → 主奏 → 独奏 → 退场，各带 `settle` 建议值），新用户一键套改，比从零配动作更快理解"场景卡该怎么写"。
3. **悬停提示带 safes 摘要**：名称旁小图标，悬停显示"该场景 recall 将影响：路由 / 通道处理 / 效果（以台面 Scene Safes 为准）"——把最容易被忽略的限制放在用户做决定的那一秒。
4. **拼音首字母搜索 + 编号直达**：输入 `dc` 出「独唱」，输入 `3` 出 3 号；两种心智模型都不用学。
5. **缺名时显示「场景 N」占位且编号可见**：绝不留空白项——空白会让用户以为选择器坏了，占位文字则明确传达"这个号还没名字"。
