## 第一部分 · 发布流程

### 1. 仓库与版本体系

项目由 **4 个 GitHub 仓库 + 1 个在线版**组成，各自独立版本号，靠「协议规范」对齐：

| 仓库（本地路径） | 角色 | 版本号 | 标签 |
|---|---|---|---|
| `glaypan/X32Remote-Protocol`（`E:\AI\workbuddy\x32遥控`） | 协议规范 + 服务端模拟器 + 网页试用版 + 发布工具链 | 规范 vX.Y / 打包 vX.Y.Z | `spec-vX.Y` |
| `glaypan/X32Remote`（`X32Remote-ios/`） | iOS App（Swift） | vX.Y.Z | `vX.Y.Z` |
| `glaypan/X32RemoteAndroid`（`E:\AI\workbuddy\X32RemoteAndroid`） | Android App（Kotlin） | versionName/versionCode | 随提交 |
| `glaypan/X32Remote-macOS`（`E:\AI\workbuddy\X32Remote-macOS`） | macOS 桌面外壳（AppKit + 内置 Python） | vX.Y.Z | `vX.Y.Z` |
| 在线试用版 | WorkBuddy sites 托管的 http-service | 随服务端代码 | — |

**版本纪律**（来自 v1.2.0 发布说明的既有做法）：某次发布只改了服务端/契约/网页时，
**不给 iOS/Android 涨版本号**——没有变化的 App 涨号只会制造噪音。此时 App 安装包
为同源码重新构建，与上一版等效。

#### 4.1 服务端 / 协议规范（协议仓，最常见）


- ⚠️ **线上 `/app.js`、`/app.css` 返回 404 是正常的**：`build_web.py` 已把 css/js
  内联进 `WEB_PAGE` 单页（约 139 KB），服务端只发这一个自包含 HTML。
  别把 404 当"没发布成功"——以首页字节数与 `/api/*` 新字段为准。

#### 4.5 一键总发布（以 iOS 为核心的完整发布）

```bash

export GITHUB_TOKEN=ghp_xxxxxxxx     # repo + workflow 两个 scope，不要勾 delete_repo

python tools/publish_release.py --dry-run    # 第一步：只看不动
python tools/publish_release.py              # 第二步：正式发布
```

它会按固定顺序做：**推送代码与标签 → 按提交 SHA 精确等待那次 CI 运行 → 下载新 IPA →
重新打包（make_release.py）→ 创建 GitHub Release → 上传全部附件**。
`--skip-build` 仅在 IPA 已确认是新版时用；`--only-release` 只建 Release。

> 为什么强制重新编译：直接拿旧 IPA 发布，用户装到的就是没有新功能的旧版本。

#### 4.6 打包与校验规则（`make_release.py`）

- `full` 包排除：`.git` / `build` / `DerivedData` / `__pycache__` / 日志 /
  **签名密钥（`x32release.jks`、`keystore.properties`、`local.properties`）**
  ——公开包里散落签名密钥等于把覆盖安装的可信度拱手让人
- Android 源码在仓库外（`ROOT` 同级的 `X32RemoteAndroid/`），存在才纳入，不阻塞发布
- 校验：`python tools/verify_zips.py`（CRC/结构/大小）+
  `cd outputs && sha256sum -c SHA256SUMS.txt`

## 第一部分·附 · macOS 内核升级实操与 zip 包规范

> 以 **2026-10-23 发布的 macOS v1.0.1** 为实例：外壳零变化，只把内置模拟器
> 从 `spec-v1.5` 升到最新内核。目标是杜绝「旧内核新外壳」。

### A. 为什么不能直接指向「最新 tag」

发布前核对发现：协议仓最新 tag 虽是 `spec-v1.6`，但它指向的模拟器只有
**6512 行**，而主线已是 **8918 行**——`spec-v1.6` 落后 12 个提交
（B0 五项 P0 修复、模块化拆包、通道参数建模 75 项、`/subscribe`、
level 161 档、dB 4 段曲线全不在里面）。直接改 `SIM_TAG=spec-v1.6`
换汤不换药。**正确做法：先把主线推上去、打一个新 spec tag，再让 CI 指向它。**

### B. 实操步骤（六步）

```bash
# ① 协议仓：跑门禁 → 推 main → 打新 spec tag（内含 8918 行模拟器）
cd "E:/AI/workbuddy/x32遥控"
rm -f X32Simulator/user_config.json
X32_TEST_PORT=10025 python X32Simulator/run_all_tests.py    # 全绿再继续
git push origin main
git tag -a spec-v1.7 -m "spec-v1.7: ..." && git push origin spec-v1.7

# ② macOS 仓：改 SIM_TAG + 涨版本号 + 同步 README + 写发布说明
#    .github/workflows/build-macos.yml: SIM_TAG "spec-v1.5" → "spec-v1.7"
#    Info.plist: CFBundleShortVersionString 1.0.0→1.0.1, CFBundleVersion 1→2
git commit -am "release: v1.0.1 — 内置内核 spec-v1.5 → spec-v1.7"

# ③ 推送 main + tag（两个 ref 各触发一次 CI，属预期）
git push origin main && git push origin v1.0.1

# ④ 等 tag 那次 CI 跑完，下载 artifact
gh run watch <run-id> --repo glaypan/X32Remote-macOS --exit-status
gh run download <run-id> --repo glaypan/X32Remote-macOS \
    -n X32Remote-macOS-unsigned -D build/dl

# ⑤ 三重验证（见下），生成 SHA256SUMS.txt，提交推送

# ⑥ 建 Release 并上传附件
gh release create v1.0.1 build/dl/X32Remote-macOS-unsigned.zip \
    SHA256SUMS.txt RELEASE_NOTES_v1.0.1.md \
    --repo glaypan/X32Remote-macOS --title "..." --notes-file RELEASE_NOTES_v1.0.1.md
```

### C. 三重验证（缺一不可）

| 验证 | 方法 | 通过标准 |
|---|---|---|
| **内核同一性** | 解包 zip，比对 `X32Remote.app/Contents/Resources/x32_simulator.py` 与协议仓源文件的 SHA256 | 逐字节一致（本次 `64e45d01…`） |
| **版本号** | 读 app 内 `Contents/Info.plist` 的 `CFBundleShortVersionString` | 与发布版本一致（1.0.1） |
| **CI 冒烟四关** | workflow 内已含：标准库导入 / 重定位断言（`sys.prefix` 在 `.app` 内）/ `otool`+`lipo` 查 minos≤10.14.6 且含 x86_64 / 无头启动 + `/api/state` | 全部 ✓ |

**闭环验证**：发布后从 release 重新下载 zip，`sha256sum` 结果必须与附件
`SHA256SUMS.txt` 一致（本次 `b62815ee…`）。

### D. 各平台 zip 包输出路径与命名规范

| 平台/用途 | 文件名 | 产出位置 | 分发位置 |
|---|---|---|---|
| macOS 桌面版 | `X32Remote-macOS-unsigned.zip` | CI：`build/X32Remote-macOS-unsigned.zip` → artifact 名 `X32Remote-macOS-unsigned`；本地：`gh run download` 落到任意目录 | macOS 仓 Release 附件 |
| 全平台完整包 | `X32Remote-v<版本>-full.zip` | 协议仓 `outputs/`（`make_release.py` 生成） | 协议仓 Release 附件 |
| 全平台成品包 | `X32Remote-v<版本>-assets.zip` | 同上 | 协议仓 Release 附件 |
| iOS | `X32Remote-unsigned.ipa` | 协议仓 `outputs/`（云端编译下载） | 协议仓 Release 附件 |
| Android | `X32Remote-<版本>.apk` | `app/build/outputs/apk/release/` → 复制到 `outputs/` | 协议仓 Release 附件 |
| 网页试用版 | `X32Remote-WebDemo.html` | 协议仓 `outputs/` | Release 附件 / 直接分发 |

命名规则：`X32Remote-<平台或用途>-[unsigned]-[v<版本>].<ext>`；
**未签名产物必须带 `unsigned`**（IPA 例外，官方容器就是 `.ipa`）；
macOS 的 CI artifact 名与 zip 文件名保持一致，`gh run download -n` 直接用
artifact 名。zip 内 macOS 是 `X32Remote.app/` 整个目录；协议仓两个包是
扁平的源码/文档/成品集合。

### E. 踩坑记录

- **`gh` 在 Git Bash 里传中文参数会被 MSYS 转换搞坏**（报
  `'E:\AI\tools\GitHub' 不是内部或外部命令`）：release 标题等参数用 ASCII，
  中文内容放 `--notes-file`；或直接用 PowerShell 调 `gh.cmd`
  （本机位于 `E:\AI\tools\GitHub CLI\bin\gh.cmd`，默认不在 PATH）
- **推送 main 和 tag 会触发两次 CI**：concurrency 按 ref 分组，互不取消，
  属预期；tag 那次才是发布构建
- **发版前先跑回归**：本次打 tag 前发现 params 组一次「失败」实为残留
  headless Chrome 占端口造成的假失败，重跑即过——假失败也要查清再打 tag
- **`gh` 在 Git Bash 里即使参数全 ASCII 也可能被打坏**：只要 PATH 里有带空格的
  目录，报错就是 `'E:\AI\tools\GitHub' 不是内部或外部命令`（v1.3.0 建 Release
  时再次命中）。**直接用 PowerShell 调 `gh.cmd`** 最稳，别在 Bash 里重试
- **`sha256sum -c` 会把空行判成 `improperly formatted`**（本机 coreutils 行为）：
  校验和文件里别留空行，注释用 `#` 行即可
- **打包脚本里的文案会过期**：`make_release.py` 的 README「本版重点」、
  `verify_zips.py` 的版本号都曾写死上一版——打新版本前先 grep 一遍
  `DEFAULT_VERSION` / `v1\.` 硬编码，否则包里会塞进一份文不对题的说明

### 6. 安装方式总览

| 平台 | 装什么 | 怎么装 | 依赖 |
|---|---|---|---|

| Windows/macOS/Linux | Android App | APK 侧载 | Android 8.0+ |

### 7. Windows

#### 7.1 模拟器（服务端）

1. **装 Python 3**：https://www.python.org/downloads/ ，安装时**勾选
   "Add Python to PATH"**（不勾则下面第 2 步找不到）
2. **启动**：把 `X32Simulator` 文件夹解压到任意位置，双击 `启动模拟器.bat`
   （找不到 `python` 时自动回退 `py -3`；都没有会提示去官网安装）
3. **防火墙**：首次运行必弹「Windows 安全中心」提示，**点「允许访问」并勾上专用网络**。
   **误点取消是手机连不上的最常见原因**——补救：Windows 安全中心 → 防火墙和网络保护 →
   允许应用通过防火墙 → 勾上 Python
4. 终端会打印该用的地址，照抄给手机：
   ```
   UDP 192.168.x.x:10023         ← App 填这个（IP+端口 10023）
   网页控制台 http://192.168.x.x:8080   ← 浏览器填这个
   ```

**可选：开机自启（无需管理员）**

```bat
install_autostart.bat    :: 注册登录时自启（schtasks 任务名 X32ConsoleService）
remove_autostart.bat     :: 移除自启
```

> `start_service.bat` 里写死了开发机 Python 路径
> （`C:\Users\Administrator\.workbuddy\binaries\python\...\python.exe`），
> 换机器用需改成自己 `python` 的路径；它把网页开在 **28080**、OSC 仍在 10023。

**手动启动 / 常用参数**

```bat
python x32_simulator.py                                   :: 默认 10023 + 8080
python x32_simulator.py --port 10023 --bind 0.0.0.0       :: 显式指定
python x32_simulator.py --bridge 192.168.50.57:10023      :: 桥接真台（电脑当代发）
python x32_simulator.py --config D:\x32\my.json           :: 独立配置（多实例联调）
```

端口优先级：**命令行参数 > `PORT` 环境变量 > 网页设置页保存的值 > 内置默认**。
命令行只影响本次运行，不改写已保存设置；网页端口填 `0` = 关闭网页控制台。

#### 7.2 Android App（Windows 上传到手机）

1. 把 `X32Remote-1.1.0.apk` 传到手机（微信文件传输 / QQ / 数据线 / 网盘）
2. 手机点 APK → 提示「禁止安装未知应用」时进 **设置 → 允许来自此来源的应用**
3. 装完桌面出现 **X32 Remote**（包名 `com.x32remote`，最低 Android 8.0）
4. 首次启动申请的网络权限：`INTERNET`（OSC 收发）、Wi-Fi 状态与多播（自动发现）、
   `WAKE_LOCK`（前台不熄屏断连）

### 8. macOS

#### 8.1 模拟器（一键安装）

```bash
bash ~/Downloads/X32Simulator/install.sh    # 路径按实际位置改
```

自动完成：检测 Python 3（缺失则自动下载安装 python.org 官方 3.11.9 包，支持 10.9+）→
复制到 `~/X32Simulator` → 桌面创建 `X32模拟器.command` 双击启动器 →
生成卸载脚本 `~/X32Simulator/uninstall.sh`。

免安装用法：把 `X32模拟器.command` 与 `x32_simulator.py` 放同一文件夹，双击即跑。

> **macOS 10.14.6（Mojave）说明**：当模拟服务器完全可行；但**不能当 iOS 开发机**
> （最高 Xcode 11.3，本项目需 Xcode 14+）。iOS 编译必须走云端 runner。

#### 8.2 macOS 桌面版（无需 Python、无需终端、无需浏览器）

1. 解压 `X32Remote-macOS-unsigned.zip`，把 `X32Remote.app` 拖入 `/Applications`
2. 首次启动：**右键 → 打开**（Gatekeeper 对未签名应用的正常提示）；
   或在终端执行一次：`xattr -dr com.apple.quarantine /Applications/X32Remote.app`
3. 限制：**仅 Intel（x86_64）、macOS 10.14.6+、未签名未公证**；免提示分发需
   Apple 开发者账号（$99/年）签名+公证
4. 配置在 `~/Library/Application Support/X32Remote/user_config.json`，
   日志在同目录 `simulator.log`（菜单「文件 → 显示模拟器日志」）

### 9. Linux

模拟器仅用 Python 标准库，无第三方依赖：

```bash
# ① 依赖（任一新版 Python 3 即可，模拟器自身无版本硬门槛）
sudo apt update && sudo apt install -y python3      # Debian/Ubuntu
sudo dnf install -y python3                          # Fedora

# ② 运行
python3 x32_simulator.py                             # 前台运行，Ctrl+C 停止

# ③ 防火墙（二选一）
sudo ufw allow 10023/udp                             # OSC，App 直连
sudo ufw allow 8080/tcp                              # 网页控制台
# 或 firewalld: sudo firewall-cmd --add-port=10023/udp --permanent && sudo firewall-cmd --reload
```

后台常驻（示例，按需改路径与用户）：

```ini
# /etc/systemd/system/x32sim.service
[Unit]
Description=X32 Remote Simulator
After=network.target

[Service]
ExecStart=/usr/bin/python3 /opt/x32/X32Simulator/x32_simulator.py
WorkingDirectory=/opt/x32/X32Simulator
Restart=on-failure
User=x32

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now x32sim
```

> ⚠️ **两个端口别混**：网页控制台 **8080（HTTP）**，App/OSC 直连 **10023（UDP）**。
> ⚠️ **浏览器发不了 UDP**：不桥接时网页操作只在电脑虚拟台内生效，控不到真调音台。

### 10. iOS（免费 Apple ID · 7 天重签）

链路：**云端 macOS 编译（GitHub Actions）→ 无签名 IPA → 本机 Sideloadly 签名安装**。

| 准备 | 说明 |
|---|---|
| iPhone | iOS 17+（App 用了 Observation 框架） |
| Apple ID | 普通免费账号，**证书 7 天有效期**，到期重签即可（数据不丢） |
| Sideloadly | Windows 上的签名安装工具，免费 |
| iTunes | 提供 Apple 设备驱动（微软商店版即可） |

步骤：① 用上面的 §4.3 得到 `outputs/X32Remote-unsigned.ipa`
（也可从协议仓 GitHub Release 直接下载）→ ② 数据线连 iPhone，Sideloadly 选 IPA +
你的 Apple ID → ③ 安装后到 **设置 → 通用 → VPN与设备管理 → 信任开发者** →
④ 第 7 天用 Sideloadly 重签一次。

> 本机网络实测：`github.com` 网页超时，但 `api.github.com` 与 git 协议通——
> 所以下载脚本全程走 API，不碰网页。

### 11. 网页试用版（零安装，任意平台）

浏览器直接打开 `X32Remote-WebDemo.html`（单文件、零依赖、可离线）。
注意它是**演示/试用**形态：浏览器发不了 UDP，卡片动作只能由电脑代发，
**不能替代原生 App 直连真台**。

## 第三部分 · 常见问题排查

| 现象 | 首选原因 | 处理 |
|---|---|---|
| 手机连不上模拟器 | Windows 防火墙点了「取消」 | 允许应用通过防火墙里勾上 Python（§7.1 第 3 步） |
| App 扫描不到台子 | 不在同一网段 / 开了手机热点 / 路由器 AP 隔离 / 手机随机 MAC | 同一路由器 Wi-Fi；关客户端隔离与随机 MAC；或**手动填 IP**（扫描靠广播，手动不需要） |
| 网页控制台打不开 | 拿 `localhost` 给手机用了 | 手机要填**电脑的局域网 IP**（`ipconfig` 看 IPv4） |
| 端口被占用 | 另一个模拟器/服务占了 10023 或 8080 | 换端口启动：`--port 10025 --web-port 28081` |
| 推子能连上但不动 | 真台 OSC 没开 | 真台 **Setup → Network** 确认 OSC 开启、端口 10023 |
| App 退后台就断 | 系统限制后台网络 | 保持前台；关电池优化（设置 → 应用 → 电池 → 不受限制） |
| macOS 打不开桌面版 | Gatekeeper 拦未签名应用 | 右键 → 打开，或 `xattr -dr com.apple.quarantine`（§8.2） |
| iOS App 突然打不开 | 免费证书 7 天到期 | Sideloadly 重签（§10） |
| iOS 装不上 | iTunes/驱动缺失 | 装微软商店版 iTunes，换根数据线 |
| Android 编译测试全红但 APK 正常 | **中文路径**导致 Gradle worker classpath 乱码 | 工程必须在纯 ASCII 路径（如 `E:\AI\workbuddy\X32RemoteAndroid`） |
| release APK 未签名 | 缺 `x32release.jks` / `keystore.properties` | 自备密钥库并在 `keystore.properties` 指向它（§4.2） |
| 改了代码行为没变 | 改的是单文件但没重新生成 / 测试跑的是旧进程 | 改 `x32sim/` 包 → `make_single.py` → 重启 → 再跑测试 |
| macOS 桌面版内核旧 | CI 的 `SIM_TAG` 落后于协议仓最新 tag | 发布前确认 `SIM_TAG` 指向最新 spec tag；v1.0.1 已修，流程见「第一部分·附」 |
| 线上 `/app.js`、`/app.css` 404 | **正常**：css/js 已内联进 `WEB_PAGE` 单页 | 以首页字节数 == `len(WEB_PAGE)` 与 `/api/*` 新字段判断是否发对 |
| 手机扫码打不开 | 二维码里的 IP 在当前网络不可达（换网段/连了热点） | 用「📋 复制地址」发到手机手输；确认手机与电脑同一 WiFi |
| 建 Release 报 `'E:\AI\tools\GitHub' 不是内部或外部命令` | Git Bash 把带空格的 gh 路径拆坏 | 改用 PowerShell 调 `gh.cmd`（§附 E） |
