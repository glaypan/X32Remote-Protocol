# 参数读取 / 写入机制 · 演出卡片与快捷方式配置说明

> 依据：`X32Simulator/x32_simulator.py`（权威实现，5900+ 行）、共享协议规范 v1.6。
> 文中所有"已实现"的行为都能在代码里指到具体函数；标 **未实现** 的部分请勿当成现状。

---

## 0. 先说结论（避免误解）

**当前真正建模并能在三端（网页 / iOS / Android 口径）流转的参数只有：**

| 参数 | 状态 | 语义 |
|---|---|---|
| 推子 fader | ✅ 已实现 | 0.0–1.0 → dB（X32 官方曲线） |
| 静音 on | ✅ 已实现 | 0/1 |
| 名称 name | ✅ 已实现 | ≤12 字符，落盘 |
| DCA 归属 | ✅ 已实现 | 8 位掩码 |
| FX 槽（算法/开关/混合比/混响时间/预延迟/阻尼） | ✅ 已实现 | 参数号随算法 |
| 场景号 scene | ✅ 已实现 | 只切号（模拟器）；真台发 `/scene/N/load` |
| 电平表 meters | ✅ 已实现 | 48 路基带 |
| 原始 OSC 透传 | ✅ 已实现 | 任意地址，仅当前控台 |

**你问的这十项——增益、反相、延时、低通、噪声门、压缩、均衡、插入、发送、Pre/Post——全部未建模**：
模拟器里没有对应状态字段、控台驱动层没有地址映射、`set` 动作的白名单里没有对应参数、预设范围也不认它们。
所以"在软件里改增益、同步到调音台"这件事**目前做不到**；现在能做的是用 `osc` 动作手工发一条原始地址（见 §9）。
§5 给出每一项要接入时缺什么、以及协议地址族与官方口径的取值范围（**均需真机标定**）。

## 1. 数据流总览

```
┌──────────┐   HTTP (250ms 轮询 / 拖动 50ms 合并)   ┌──────────────────┐
│  网页 UI  │ ───────────────────────────────────▶ │  x32_simulator   │
│ iOS/安卓  │ ◀─────────────────────────────────── │  （服务端 + 虚拟台）│
└──────────┘        /api/state 全量快照              └────────┬─────────┘
      │ OSC 直连（App 自己发，不经模拟器）                     │
      └──────────────────────────────┐                      │ UDP 10023
                                     ▼                      ▼
                              ┌──────────────────────────────────┐
                              │  真台 X32/M32（可选）              │
                              └──────────────────────────────────┘
```

三种运行形态，同步方式完全不同：

| 形态 | 参数怎么到"调音台" | 典型用途 |
|---|---|---|
| **A. 纯模拟** | 只写内存里的 `STATE`，不往外发 | 演示、排练、无硬件调参 |
| **B. 桥接真台** | 模拟器 `_bridge_forward()` 把写入转成 OSC 发往真台；真台变化由回读线程同步回来 | 网页/手机上控制真台（推荐） |
| **C. App 直连** | iOS/Android 直接用 `X32Client` 发 OSC 到真台，不经过模拟器 | 现场只用手机 |

## 2. 写入：界面改了参数，怎么同步到调音台

### 2.1 六层链路（以拖动通道 5 推子为例）

| # | 层 | 做什么 | 代码位置 |
|---|---|---|---|
| 1 | 交互层 | 拖动 50ms 合并，发 `POST /api/setbatch {sets:[{kind:"ch",param:"fader",idx:5,value:0.72}]}` | 前端 `pushBatch` |
| 2 | 校验层 | `SET_KINDMAP[group][param]` 查表得 `ch_fader`；`target_exists()` 预检编号是否在当前控台范围内 | `do_POST` |
| 3 | 归一化层 | `_clamp01` 钳 0–1、`_truthy` 转 0/1、`_finite` 吃 NaN/Inf | `set_value` |
| 4 | 状态层 | 加锁写 `STATE.ch[5]["fader"]`；DCA 手动推会级联成员（按 dB 差量） | `set_value` / `_dca_cascade` |
| 5 | 广播层 | `_push_manual_now()` 节流后推给 `/xremote` 订阅者（模拟真台"面板一动就推送"） | `_push_manual_now` |
| 6 | 转发层 | 桥接开着 → `_bridge_forward()` → `addr_for_write()` 取地址 → UDP 发真台，并登记回声抑制 | `_bridge_forward` |

### 2.2 触发时机

| 触发 | 时机 | 说明 |
|---|---|---|
| 拖动推子 | 拖动中每 50ms 合并一批 | 一次 `setbatch` 最多 128 条，越界条目跳过并计入 `applied` |
| 点静音/开关 | 立即单发 `/api/set` | |
| 控制键（快捷方式） | 点一下一步；长按 500ms 后每 150ms 连发 | `apply_key()` |
| 卡片动作 | 按时间轴（`at` 偏移或顺序） | 渐变类由主循环 0.05s tick 插值，不阻塞 |
| 预设回归 | 点"⏪ 回归"或卡片 `preset` 动作 | 瞬时项立即，推子按秒滑回 |
| OSC 外部写入 | App/调音台软件发来即处理 | 有参数=写，无参数=读 |

### 2.3 取值范围与钳制（已实现部分）

| 参数 | 传输值 | 钳制 | 默认 |
|---|---|---|---|
| 推子 | 0.0–1.0 | `_clamp01` | 0.75（0 dB） |
| 静音 | 0/1 | `_truthy` | 1（开） |
| 名称 | 字符串 | 去空白 + 截 12 字符 | 出厂名表（15=音乐、Bus15=耳返…） |
| DCA 掩码 | 0–255 | `& 0xFF` | 每 8 路一组 |
| FX 混合比 | 0–1 | `_clamp01` | 0.25 |
| 混响时间 | 秒（原生） | 按算法 `tmin/tmax` 钳 | HALL 2.4s / PLATE 1.8s … |
| 预延迟 | 毫秒 | 按算法钳 | 12–25ms |
| 阻尼 | 0–1 | 按算法钳 | 0.30–0.55 |
| 场景号 | 1–99 | 1–99 | 1 |

### 2.4 失败处理

| 情况 | 行为 |
|---|---|
| 编号越界（如 ch 40） | `/api/set` 返回 **400** 并说明范围；`setbatch` 跳过该条，`applied` 计数少 1 |
| 未知 kind | 日志 `SET 未识别的写入: kind=... (已忽略)` —— **不静默** |
| NaN / Infinity | 入口 `_finite` 兜住；输出层 `_sanitize_snapshot` + `json.dumps(allow_nan=False)` 双闸（历史事故：NaN 曾让界面永久卡死） |
| 控台未标定（Wing/Yamaha/A&H） | `profile.ready=False` → 拒绝所有写入并记日志；`pending()` 列出还缺哪些地址 |
| 桥接未连 | 本地照常改，不转发；`/api/state.bridge.live=false` 供 UI 灰显 |
| 真台不可达 | UDP 无回包；桥接线程每 30 秒提示一次（查 IP/网线/同网段） |
| 卡片动作非法 | `_clean_actions` 丢弃并给出人话原因，透到前端 toast |

## 3. 读取：三条通路

### 3.1 HTTP 全量快照（网页/App 主用）

- **频率**：250ms 一次 `GET /api/state?logseq=N`
- **内容**：79 路推子/静音、名称、FX、场景号、卡片、预设列表（**不含 preset 的 data**）、bridge、ports、events、日志增量
- **增量优化**：`logseq` 只回新增日志；预先算好的 `meters` 直接下发
- **防冲突**：前端对正在编辑的输入做脏标记（如端口输入框），轮询不覆盖用户输入
- **失败**：请求失败静默重试（下一轮），不弹错；界面保留上一帧

### 3.2 OSC 查询（App / 调音台软件）

- **触发**：收到无参数消息即视为读，如 `/ch/05/mix/fader`
- **单条**：回一条 Message；**通配符**（`/ch/*/mix/fader`）回一个 Bundle（32 条）
- **不支持的地址**：记日志 `(当前控台不支持 N 个匹配目标, 无回包)`，**不回错误包**（真台行为）
- **未识别地址**：日志 `(未识别,忽略)`

### 3.3 桥接回读（真台 → 本地）

| 环节 | 细节 |
|---|---|
| 建立 | `bridge_start()` → `_bridge_full_sync()` 发一轮 GET Bundle，把真台全量填进本地 |
| 保活 | 每 **5 秒** 发 `/xremote`（真台 10 秒无保活会断开遥控链接） |
| 变更同步 | 回读线程收包 → `match_address()` → `_bridge_apply_readback()` |
| 回声抑制 | `_fwd_is_echo()`：值 + 时间双判定，吸收"自己刚发出去又读回来"的包，避免自我覆盖 |
| 冲突 | 该路正被卡片渐变驱动 → 标记"手动接管"，冻结该路并在网页生成 `⚠️` 事件 |
| 存活判定 | `last_recv` 8 秒内有包 → `live=true` |

### 3.4 变更推送（模拟真台主动推）

- `_push_state_diffs()` 每次 tick 对比 `PUSH_CACHE`，值变了才推（阈值 1e-4）
- 订阅者来自 `/xremote`、`/subscribe`、`/meters`，**30 秒** 无续期自动清理
- 电平：`/meters/1` 订阅后每 **150ms** 推 48 路 blob；发 `/meters/1 i 0` 退订

## 4. 读取与写入的"触发时机"对照

| 动作 | 读？ | 写？ | 时机 |
|---|---|---|---|
| 网页拖推子 | — | ✅ 本地 + 桥接转发 | 拖动中 50ms 合并 |
| 网页打开/切页 | ✅ 全量快照 | — | 250ms 轮询 |
| App 连上真台 | ✅ 订阅 + 首次全量 | — | 连上即拉 |
| App 推推子 | — | ✅ 直发真台 | 松手/拖动节流 |

| 预设回归 | — | ✅ 范围内 | 点按 / 卡片动作 |
| 真台面板动 | ✅ 回读 | — | 真台推送/轮询，5 秒保活期间 |
| 定时卡片 | — | ✅ | 延时到点 / 到 HH:MM |

## 5. 十个参数的逐项现状（重点）

> ⚠️ **统一前提**：以下地址族与取值范围来自 **X32 官方 OSC 表口径**，本项目**未在真机标定过**。
> 按项目规则（"未标定的控台一律拒绝写入"），落代码前必须：真机读一遍 → 台面手动改一次 → 抓包比对 → 才能写进
> `ConsoleProfile.addr()` 并声明 `caps`。默认值尤其不可照抄：它随固件与本机场景变化。

所有参数都缺同一批层：**状态字段 → 地址映射 → 白名单 → 预设参数 → UI 控件 → 标定**。下表只写差异。

### 5.1 增益（前置放大 / Trim）

| 项 | 内容 |
|---|---|
| 现状 | **未实现**（无字段、无映射、无控件） |
| 地址族 | `/ch/NN/preamp/trim`（浮点 dB） |
| 官方范围 | −18 … +48 dB |
| 默认 | 0 dB（出厂场景） |
| 注意事项 | 与模拟增益（analog gain）是两个概念；本机若开了"增益补偿"行为会不同，必须真机确认 |
| 要接入 | `STATE.ch[i]["trim"]`、`caps += ("preamp",)`、UI 旋钮、预设参数 `trim` |

### 5.2 反相（Polarity / Invert）

| 项 | 内容 |
|---|---|
| 现状 | **未实现** |
| 地址族 | `/ch/NN/preamp/invert`（int 0/1） |
| 范围/默认 | 0（正相）/ 1（反相）；默认 0 |
| 要接入 | `STATE.ch[i]["invert"]`、UI 一个反相按钮（卡片 `set` 可直接复用，param 加 `invert`） |

### 5.3 延时（Channel Delay）

| 项 | 内容 |
|---|---|
| 现状 | **未实现** |
| 地址族 | `/ch/NN/delay/on`（int）、`/ch/NN/delay/time`（浮点，毫秒） |
| 官方范围 | 0 … 500 ms；默认 0 |
| 要接入 | `STATE.ch[i]["delay"] = {"on":0,"ms":0.0}`；UI 需"毫秒 ↔ 距离"换算显示（声速 343 m/s） |

### 5.4 低通（Low-Pass / 高切）

| 项 | 内容 |
|---|---|
| 现状 | **未实现**。注意：X32 通道 EQ 是「4 段参量 + 低切(HPF) + 高切(LPF)」，"低通"对应**高切** |
| 地址族 | `/ch/NN/eq/highcut/on`（int）、`/ch/NN/eq/highcut/f`（浮点 Hz） |
| 官方范围 | 20 Hz … 20 kHz（对数）；默认关闭、20 kHz |
| 要接入 | 与 EQ 一起做（同一组控件），见 5.7 |

### 5.5 噪声门（Gate）

| 项 | 内容 |
|---|---|
| 现状 | **未实现** |
| 地址族 | `/ch/NN/gate/on`、`/gate/thr`（dB）、`/gate/range`（dB）、`/gate/attack`（ms）、`/gate/hold`（ms）、`/gate/release`（ms）、`/gate/keysrc` |
| 官方范围 | thr −80…0 dB；range −60…0 dB；attack 0…120 ms；hold 0…2000 ms；release 5…4000 ms |
| 默认 | 出厂关闭（on=0），其余参数随场景，**必须读回确认** |
| 要接入 | 7 个字段 + 一个"门限"面板；卡片要写它就得给 `set` 加 `gate_thr` 之类的 param 白名单 |

### 5.6 压缩（Dynamics / Comp）

| 项 | 内容 |
|---|---|
| 现状 | **未实现** |
| 地址族 | `/ch/NN/dyn/on`、`/dyn/mode`、`/dyn/thr`(dB)、`/dyn/ratio`、`/dyn/attack`(ms)、`/dyn/hold`(ms)、`/dyn/release`(ms)、`/dyn/mix`(%)、`/dyn/gain`(dB) |
| 官方范围 | thr −60…0 dB；ratio 1…20；attack 0…120 ms；release 5…4000 ms；mix 0…100%；gain −12…+12 dB |
| 默认 | 出厂关闭；其余随场景 |
| 要接入 | 9 个字段；`mix` 是并行压缩的关键（0% = 干声） |

### 5.7 均衡（EQ 4 段 + 低切/高切）

| 项 | 内容 |
|---|---|
| 现状 | **未实现** |
| 地址族 | `/ch/NN/eq/on`；`/eq/1..4/g`(dB)、`/eq/1..4/f`(Hz)、`/eq/1..4/q`、`/eq/N/type`；`/eq/lowcut/on|f`、`/eq/highcut/on|f` |
| 官方范围 | 增益 −15…+15 dB；频率 20…20 kHz（对数）；Q 0.3…10；类型（钟形/搁架等）按固件枚举 |
| 默认 | EQ 关闭；各段 0 dB / 频率出厂分布 |
| 要接入 | 4 段 × 3 参数 + 2 个滤波器 = 14 个字段；建议做成"一屏 EQ 曲线"而不是 14 个数字框；预设范围要加 `eq` 参数类型（**整段存**，像 FX 整槽那样，否则半截 EQ 更危险） |

### 5.8 插入（Insert）

| 项 | 内容 |
|---|---|
| 现状 | **未实现** |
| 地址族 | `/ch/NN/insert/on`、`/insert/pos`、`/insert/sel` |
| 范围 | on 0/1；pos 枚举（插入点在 EQ 前/后等）；sel 为插入槽选择 |
| 默认 | 关闭 |
| 要接入 | 只读"是否开启 + 位置"即可覆盖大部分需求；真正处理链要看效果器参数（不在本机能力内） |

### 5.9 发送（Sends，通道 → Mix Bus）

| 项 | 内容 |
|---|---|
| 现状 | **未实现**（这是当前最大的能力缺口：32 通道 × 16 Bus = 512 条） |
| 地址族 | `/ch/NN/mix/BB/level`（0…1）、`/ch/NN/mix/BB/pan`、`/ch/NN/mix/BB/on` |
| 范围/默认 | level 0…1（dB 换算同推子曲线，**待标定**）；默认 level 0（−∞）、pan 居中、on=1 |
| 要接入 | `STATE.ch[i]["send"] = {bus: {"level":0.0,"pan":0.0,"on":1}}`（512 × 3 个值，注意配置文件体积与轮询带宽） |
| 预设影响 | 若纳入预设，全量 count 会从 158 涨到 1500+，**必须**默认不勾、且列表接口不能下发 data |

### 5.10 Pre / Post（发送取点）

| 项 | 内容 |
|---|---|
| 现状 | **未实现** |
| 地址族 | 与发送同一族（`/ch/NN/mix/BB/...` 下的 tap 字段），具体字段名随固件；台侧也可能有"按 Bus 全局 tap"的开关 |
| 范围 | Pre（推子前）/ Post（推子后，出厂默认） |
| 为什么危险 | Pre/Post 决定"推子动的时候监听送量是否跟着变"。如果只做发送电平不做 tap，用户会以为"我推了主推子怎么返听没变" |
| 要接入 | 先真机确认粒度（通道×Bus 还是 按 Bus），再定数据模型；预设里建议**整条 Bus 的发送一起存** |

## 6. 演出卡片配置

### 6.1 可绑定的参数类型（当前）

| 目标 | 卡片里怎么写 | 范围 |
|---|---|---|
| 输入通道 | `set` 的 `group:"ch"`、`id:1-32`、`param:"fader"|"on"` | 推子/静音 |
| Mix Bus | `group:"bus"` 1-16 | 推子/静音 |
| DCA | `group:"dca"` 1-8 | 推子/静音 |
| Aux In / USB / FX 返回 / Matrix / Main | `group` 对应 + `id` | 推子/静音 |
| DCA 归属 | `group:"ch"`、`param:"dca"`、值为位掩码 | 仅输入通道 |
| FX 槽 | `group:"fx"`、`param:"type"|"name"|"on"|"mix"|"time"|"predelay"|"damp"` | 整槽属性 |
| 场景 | `group:"scene"` 或专用 `scene` 动作 | 全局 / 局部 |
| 名称 | 仅 FX 槽可写字符串；通道名走 `/api/name` 或 OSC | ≤12 字符 |
| 任意地址 | `osc` 动作（地址自填） | 仅当前控台，⚠️ 控台专有 |

**不能绑定**：增益、反相、延时、门、压缩、EQ、插入、发送、Pre/Post（未建模，见 §5）。

### 6.2 三种调用方式

1. **点按卡片** —— 立即跑；含"全体"类动作的卡需长按 0.8 秒确认（防误触）
2. **定时** —— `mode:"delay"` 延时 N 秒 / `mode:"clock"` 到 HH:MM，可在卡片页取消
3. **链式** —— 卡片 `next` 指向下一张，执行完自动接续（防环上限 16）

### 6.3 时间轴规则

- tick 0.05s；`start = at ?? cursor`，`cursor = start + dur`（无 `at` 的顺序排布，有 `at` 的并行）
- `wait` 是纯等待占位（不写任何值）
- 渐变由主循环插值（4 条曲线：linear / ease_out / ease_in / smooth），**不阻塞**
- 执行前自动存"撤销点"（最多 5 个），事后可一键滑回

### 6.4 卡片动作与冲突（简）

- 手动动正在渐变的通道 → **只冻结那一路**，其余继续；生成 `⚠️ 手动接管` 事件
- 中途再点一次 = 停止（推子停在当前位置，不回弹）
- 启动新卡片会 **停掉上一张**（`SHOW_STOP`），不会两张同时驱动同一路

## 7. 快捷方式（控制键）配置

| 项 | 内容 |
|---|---|
| **可绑定参数** | **只有推子**（8 类：ch / bus / dca / main / auxin / usb / fxret / mtx） |
| **不可绑定** | 静音、FX、场景、EQ 等（`QUICK_KEY_KINDS` 只收 8 个 `*_fader`） |
| 参数 | `step_db`（默认 3 dB，可改）、`ramp`（默认 0.4 秒渐变，0=瞬间）、`sign`（±1） |
| 范围 | 结果钳在 −90…+10 dB；内部用 `db_to_fader()` 换算行程 |
| 调用 | 点一下 = 按步长调整一次；**长按 500ms 后每 150ms 连发**；可按方向做"耳返增大/减小"两个键 |
| 落盘 | `user_config.json.quickKeys`，重启不丢 |
| 与卡片的关系 | 控制键写入按 `source="manual"` 处理：若该路正被卡片渐变，会触发"手动接管"并冻结它（这是期望行为） |

## 8. 批量应用

| 方式 | 上限 | 语义 | 失败处理 |
|---|---|---|---|
| `/api/setbatch` | 128 条/次 | 批量写推子/静音 | 越界条目跳过，返回 `applied` 数量 |
| `fade_all` / `unmute_all` | 79 路 | 全体推子 / 全体取消静音 | 不支持的目标按控台 `addr()` 过滤 |
| 卡片多目标 | `chs[]`/`buses[]`/`dcas[]` | 同类多选 | 越界跳过并写日志 + `_skip_note` 提示 |
| 预设回归 | scope 内全部 | 按范围应用 | 范围外不动；空范围保存被 400 拒 |

## 9. 冲突与覆盖矩阵（谁赢）

| 场景 | 结果 | 依据 |
|---|---|---|
| 卡片渐变 vs 人手推（含真台面板） | **人手赢**：冻结该路 + `⚠️` 事件；其余通道继续 | `_check_manual_takeover` / `INTERRUPTS` |
| 两张卡片同时开 | **后开的赢**：启动新卡先 `SHOW_STOP` 停旧卡 | `/api/show` |
| 预设回归 vs 卡片渐变 | **谁后写谁赢**：回归用 `source="action"`，不触发冲突检测，会覆盖渐变中的值 | `_recall_body` |
| 预设回归范围外 | **不动**（这是"局部"的全部含义） | `_snap_items` 只返回范围内的键 |
| 局部场景 vs 全局场景 | 局部**不发场景号**，只应用预设范围；找不到预设 → 跳过（绝不退化全局） | `_exec_instant` |
| 桥接回声（自己发出去又读回来） | **吸收**，不当作外部修改 | `_fwd_is_echo`（值 + 时间双判） |
| 桥接回读 vs 本地刚做的写入 | 值相同则吸收；值不同则视为真台干预 | 同上 |
| 手动推 DCA | 成员按 **dB 差量** 级联（不是按百分比） | `_dca_cascade` |
| 卡片推 DCA | **不级联**（`source="action"`），只在真台侧生效时由回读体现 | `set_value` 分支 |
| 同一卡片内 `at` 并行写同一路 | 后执行者覆盖，无仲裁 | 时间轴顺序 |

## 10. 把这十项接进来的落地清单（按层，1→8）

1. **状态模型**：`MixerState.ch[i]` 增加 `trim/invert/delay/eq/gate/dyn/insert/send`（按需，别一次全上）
2. **控台驱动**：`X32Profile.addr()` 补分支；`caps` 增加对应能力名；未标定控台保持 `ready=False`
3. **API 白名单**：`SET_GROUPS` / `SET_PARAMS` 增加 param；`SET_KINDMAP` 同步
4. **预设范围**：`PRESET_GROUP_PARAMS` 增加参数类型（建议 EQ/门/压缩**整段存**，避免半截）
5. **状态下发**：`snapshot_state` 增加字段；注意 250ms 轮询带宽（发送若全量下发会很重，建议按页/按通道懒加载）
6. **UI**：控件 + 单位（dB/ms/Hz/%）+ 越界即时提示；卡片 `set` 无需新动作，白名单通了就能写
7. **真机标定**：读回 → 台面手改 → 抓包比对 → 写入地址表；把结果记进规范 §14
8. **回归**：`test_presets.py` 风格加断言（写入回读一致、范围不越界、未标定控台被拒）

## 11. 风险提示

1. **真台场景 recall 会覆盖除 Scene Safes 外的一切**；我们做的"局部"是客户端模拟，不是真台行为，别混为一谈
2. **Pre/Post 的粒度**（通道×Bus 还是按 Bus）必须先确认——搞错会让"推子前/后"整体行为反过来
3. **发送电平的 dB 换算**与推子曲线不一定相同，必须实测
4. **不同固件地址差异**：X32 4.0 与更早版本在 dyn/eq 的字段命名上有出入
5. **预设体积**：纳入发送后全量值数量会从 158 涨到 1500+，`/api/state.snapshots[]` 绝不能下发 `data`（当前设计已如此）
